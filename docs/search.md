# 검색 (Mac)

코드: `src-tauri/src/search.rs`. 색인 파일: `<앱 데이터>/search.sqlite3`(보관함 밖, 언제든 다시 만들 수 있음)

## 색인

- `docs`: 문서 id, 이름, 세션, 종류, 만든 시각, 지문(manifest, edits, processing 수정 시각)
- `pages`: FTS5 가상 표, `tokenize = 'trigram'`. 원문(`text`)은 결과 보여 주기용이라 색인하지 않고, 공백을 빼고 소문자로 바꾼 `compact`만 색인합니다

trigram은 형태소 분석 없이 세 글자 조각으로 색인해 "센터"가 "데이터센터" 안에서 찾아집니다. OCR이 띄어쓰기를 자주 다르게 읽어(데이터 센터, 데이터센터) 색인과 검색어 모두 공백을 뺍니다.

다시 색인하는 때: 처리가 끝났을 때, edits를 저장했을 때(이름 바꾸기), 앱을 켤 때(지문이 바뀐 문서만, 사라진 문서는 뺌). 표 형식을 바꾸면 `INDEX_VERSION`을 올립니다. 옛 표를 지우고 새로 만듭니다.

## 찾기

- 검색어도 공백을 빼고 소문자로 바꿉니다
- 세 글자 이상: `compact MATCH "<검색어>"`(trigram 색인). 두 글자 이하: `LIKE`로 훑기(trigram 색인을 못 탐)
- 문서 이름과 세션: 초성 검색(`ㅎㅂㄹ`, `한ㅂ`). 문서 수는 많지 않아 Rust에서 훑습니다. 본문은 결과가 너무 많아져 초성 검색에서 뺐습니다
- 결과: 이름이 맞은 문서를 먼저, 그다음 최신순. 문서마다 최대 20쪽, 쪽마다 첫 자리 앞뒤 36글자 조각과 강조 구간. 강조는 원문에서 공백을 건너뛰며 맞춰 찾습니다(`find_spans`). 글자 위치를 화면(UTF-16)으로 넘기지 않으려고 `{ text, hit }` 조각으로 보냅니다
- 결과를 누르면 그 쪽을 열고, 문서 화면이 같은 규칙으로 OCR 줄을 찾아 그림 위에 노란 상자로 표시합니다
