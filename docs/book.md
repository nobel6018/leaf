# 책 쪽 번호 확인

삼각대에 iPhone을 두고 300쪽 책을 찍다 보면 두 장을 한 번에 넘기거나(빠진 쪽) 같은 쪽을 두 번 찍습니다(겹친 쪽). 처리와 OCR이 끝난 책 문서에서 인쇄된 쪽 번호를 읽어 이런 사고를 알려 주고, 사용자가 누르면 쪽 번호 순서로 페이지를 정렬합니다.

코드: `src-tauri/src/book.rs`(분석과 명령), `src/views/BookPanel.tsx`(화면). 종류가 `book`인 문서의 오른쪽 칸에만 보입니다.

## 명령

| 명령 | 하는 일 |
|---|---|
| `book_page_report(documentId)` | 출력 페이지별 쪽 번호와 신뢰도, 빠진 번호, 겹친 번호, 순서가 어긋난 페이지. 아무것도 쓰지 않는다 |
| `sort_by_page_numbers(documentId)` | 쪽 번호 순서를 `edits.json`의 `pageOrder`로 쓰고(`Edits::load`, `Edits::save`) 처리 줄에 세운다. 사용자가 단추를 누를 때만 부른다 |

정렬 뒤에는 처리 줄이 `processing.json`의 출력 순서를 새 순서로 다시 씁니다. 바뀐 페이지가 없으면 이미지는 다시 만들지 않습니다. PDF, 검색, AI 묶음은 그 순서를 따릅니다. 정렬은 `busy::start("쪽 번호 정렬: ...")`로 등록합니다.

## 번호 읽기 (`parse_line`, `candidates`)

`ocr/<출력 id>.json`의 줄 가운데 높이가 위 12% 또는 아래 12% 안에 있는 줄만 봅니다.

| 모양 | 예 | 점수 |
|---|---|---|
| 숫자만 | `57`, `- 57 -`, `57 \|`, `\| 57`, `p. 57`, `57쪽`, `[ 203 ]`, 전각 숫자 | 1.0 |
| 혼동 글자가 낀 숫자(4자 이하, 진짜 숫자 하나 이상) | `5B`→58, `l2`→12, `1O3`→103 | 0.7 |
| 로마 숫자(앞쪽 머리말, 차례) | `xiv`, `IX`. 낱자는 0.55배, 대문자는 0.85배 | 0.8 |
| 머리글 줄의 맨 앞이나 맨 뒤 숫자 | `57 \| 3장 제목`, `제목 \| 58` | 0.6 |

후보 신뢰도는 OCR 줄 신뢰도 x 모양 점수 x 가장자리 가까움입니다. 로마 숫자는 xl(40)까지만 받습니다. 낱자 `l`(50)은 숫자 1을 잘못 읽은 경우가 많아서입니다. 펼친 책을 나누지 못해 통째로 남은 장에 왼쪽 반 n, 오른쪽 반 n+1이 있으면 두 쪽을 덮는 후보(`span` 2, 표시 `56-57`)로 합칩니다.

## 순서로 고치기 (`analyze`)

1. 페이지마다 신뢰도가 가장 높은 후보를 고릅니다. 후보가 여럿이면 앞뒤 3장 안의 후보와 이어지는 쪽에 0.5를 더합니다(머리글의 장 번호 대신 쪽 번호)
2. 앞뒤 가장 가까운 번호가 사이 출력 수와 꼭 맞게 이어지면(56, ?, 58) 그 자리 값을 압니다. 읽은 값이 글자 하나 차이(바뀜, 빠짐, 더함)거나 혼동 글자였으면 고치고, 전혀 다른 숫자(표 번호, 연도)면 같은 페이지의 다른 후보를 쓰거나 못 읽은 것으로 둡니다. 번호를 지어내지 않습니다
3. 원본 한 장 안의 출력끼리 맞춥니다. 펼친 책 왼쪽이 n이면 오른쪽은 n+1, 3단 접지 k면은 n+k입니다. 정렬 값(번호 - 원본 안 자리)이 다르면 장 밖 이웃과 꼭 맞게 이어지는 수가 많은 쪽을 믿고, 나머지를 글자 하나 차이일 때만 고칩니다
4. 바로 옆이 빠진 쪽이나 겹친 장이라 자리가 꼭 맞지 않으면, 양쪽 이웃이 다 있을 때만 한쪽에서 기대한 값으로 고칩니다(그 값이 다른 쪽 이웃과도 어긋나지 않아야 함)
5. 앞뒤가 서로 맞는데 혼자 20 넘게 동떨어진 숫자는 쪽 번호가 아니라고 보고 버립니다

고친 번호는 `corrected: true`이고 화면에 "고침(읽은 글자)"으로 보입니다. 신뢰도는 앞뒤 번호와 이어지면 그대로, 이웃이 없으면 0.8배, 이웃과 안 맞으면 0.6배입니다.

## 검사

- 겹침: 같은 번호(두 쪽을 덮는 장은 두 번호 다)가 앞에 이미 있다. 원본 id도 같이 줘서 화면이 "페이지 빼기"할 장을 고르게 합니다
- 순서 어긋남: 겹친 뒤쪽 사본을 뺀 번호들로 가장 긴 증가 부분열(O(n log n))을 잡고, 거기 못 든 페이지
- 빠진 번호: 종류(로마, 아라비아)마다 덮인 번호를 모아 사이가 빈 곳. 그 사이(문서 순서)에 번호를 못 읽은 장이 있으면 `unnumberedBetween`에 세고, 빈 번호 수 이하면 `likelyUnnumbered`(장 첫 페이지, 그림 페이지는 번호가 없곤 함). `missing`에는 번호 없는 장으로 설명되지 않는 빈 번호만 넣습니다

## 정렬과 펼친 면 (`plan_order`)

`pageOrder`는 원본 페이지 id 단위입니다. 펼친 책은 원본 한 장이 왼쪽, 오른쪽 출력 두 장(`-L`, `-R`)이고, 3단 접지는 세 장(`-P1`~`-P3`)입니다. 출력 하나만 따로 옮길 수 없으므로 원본 한 장마다 정렬 값 하나를 정합니다.

- 원본의 정렬 값 = 그 장 출력들의 (종류, 번호 - 원본 안 자리) 중 가장 작은 값. 자리는 `Whole`, `Left`, `Panel(0)`이 0, `Right`가 1, `Panel(k)`가 k입니다. 왼쪽 56, 오른쪽 57이면 둘 다 56이고, 왼쪽을 못 읽고 오른쪽만 57이어도 56입니다
- 종류는 로마 숫자가 아라비아 숫자보다 앞입니다(머리말 i~xii 뒤에 본문 1쪽)
- 번호를 하나도 못 읽은 원본은 지금 바로 앞 원본에 붙어 같이 움직입니다(장 첫 페이지, 그림 페이지). 맨 앞의 번호 없는 원본(표지)은 맨 앞에 남습니다
- 같은 값이면 지금 순서를 지킵니다(안정 정렬). 두 번 찍은 장은 정렬 뒤 나란히 붙어 하나를 지우기 쉽습니다
- 아직 처리 전이라 출력이 없는 원본도 순서에서 빠지지 않습니다. 지금 바로 앞에 있던 원본 뒤에 다시 넣습니다(`reinsert_unprocessed`)

빠진 쪽을 나중에 iPhone으로 찍으면 문서 끝에 붙습니다(`pageOrder`에 없는 새 페이지는 뒤로, `Edits::apply`). 받아서 처리와 OCR이 끝난 뒤 "쪽 번호 순서로 정렬"을 누르면 제자리로 들어갑니다.

## 합성 평가

`src-tauri/src/book.rs` 테스트. 실제 책은 쓰지 않고 합성 `OcrPage`를 만듭니다.

```sh
cargo test -p leaf --lib book -- --nocapture
```

펼친 책 300쪽(원본 150장) 20권. 장마다 4% 건너뜀, 3% 두 번 찍음. 쪽마다 6% 번호 없음, 5% 혼동 글자(8→B, 0→O, 1→l), 3% 끝자리 오독, 10% 머리글에 장 번호.

| 지표 | 결과 (2026-11-05) |
|---|---|
| 쪽 번호 맞음 / 틀림 / 못 읽음 (인쇄된 5579쪽) | 99.2% / 0.2% / 0.6% |
| 빠진 쪽 재현율 | 98.0% (화면 목록 기준, 오탐 11건 / 20권) |
| 두 번 찍은 장 재현율 | 97.4% (오탐 12건 / 20권) |
| 순서 어긋남 오탐 | 6 / 5900장 |

남은 오류는 대부분 같은 장 두 쪽을 함께 잘못 읽어(218, 219를 211, 212로) 서로 이어지는 경우입니다. 앞뒤 원본 장과 견주는 장 단위 보정을 더하면 줄일 수 있습니다.

## 한계

- 실제 책으로는 아직 확인하지 않았습니다. 위 수치는 합성 OCR 결과 기준이고, Vision OCR이 작은 쪽 번호를 얼마나 놓치는지는 모릅니다
- 쪽 번호가 바깥 여백 옆(세로 가운데)에 있는 책, 번호가 그림 안에 있는 책은 못 읽습니다
- 곡면 보정이 가장자리를 잘라 쪽 번호가 날아가면 번호 없는 장이 됩니다
- 아라비아 숫자가 1부터 다시 시작하는 책(부록마다 쪽 번호를 새로)은 겹침으로 보입니다
